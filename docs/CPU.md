# CPU の設計と検証

## 実装したもの

GUI の開始画面から Easy / Normal / Hard の CPU 対戦、または従来の2人対戦を選べます。
CPU の手札・捨て札は表示されません。思考は別プロセスで行い、描画とイベント処理を止めません。
Esc でメニューへ戻れます。ワーカーが失敗した場合は R で再試行できます。
ターミナル版は従来どおり対人戦です。

| 設定 | 通常ターンの方式 | 思考時間の目安 | サンプル上限 | 探索する有望候補数 |
|---|---|---|---|---|
| Easy | 配置の特徴を採点して選択 | 通常は即時、FL は約0.25秒まで | 0 | 1 |
| Normal | Monte Carlo ロールアウト | 約1.5秒まで | 64 | 16 |
| Hard | 同じ方式で探索量を増加 | 約5秒まで | 256 | 32 |

時間は探索用の目安です。プロセス初回起動・候補生成・現在処理中の評価の分だけ超える場合があります。
Hard がどの局面でも Normal に勝るという保証はありません。

### 通常ターン

最初の5枚の配置は232通り（上段の容量を超えるものを除く）、以降の3枚から2枚を置く手は
最大27通りです。まず現在ターンの合法な配置と捨て札をすべて列挙します。
途中のターンでは役の素材、同スート、連続した数字、段の強弱関係などで候補を絞ります。
未知カードをシャッフルして将来の3枚配牌をサンプルし、それぞれの候補を最後まで進めます。
継続方針はその時点の配牌だけを見て決定し、その先の配牌を参照しません。
候補間で同じ配牌サンプルを使い、時間切れになった途中の比較バッチは採用しません。

得点にはゲーム本体の役・ファウル・ロイヤリティを使い、各段の勝敗とスクープを反映します。
次回ファンタジーランドの価値は14/15/16/17枚について7/9/11/13点という暫定評価です。
これは学習済みの正確な長期価値ではありません。
最終ターンは配置候補を省略せず評価します。相手の完成盤面が公開済みなら実際の対戦得点を使います。
未完成・非公開の場合は、既知カードを除いた未知カードから相手の完成盤面をサンプルし、
すべての自分の候補を同じ相手サンプルに対して比較します。Easy や時間切れで
完全な比較バッチを得られない場合は、自分の盤面評価に戻ります。

### ファンタジーランド

配られた14〜17枚から、下段5枚・中段5枚・上段3枚の互いに重複しない組を探索します。
初期候補を確保した後、5枚組の役評価をキャッシュし、下段 ≥ 中段 ≥ 上段の条件を満たす候補を比較します。
時間制限と下段候補数の上限があるため、全組合せの最適解保証はありません。
探索時間がゼロでも配置枚数・重複・捨て札数を満たす手を返しますが、ファウル回避は保証されません。
継続条件と継続時の枚数維持はゲーム本体の Player.evaluate_board を利用します。

## 非公開情報の境界

CPU ワーカーへ送る Observation は整数のカードIDとタプルだけで構成します。
含むものは自分の配置済みカード、現在の配牌、自分の捨て札、相手の公開済み盤面、自分のFL枚数です。
Game / Deck / 相手の Player オブジェクトは送りません。
同じストリートで相手が置いた未公開カードは、配置された段の情報も除外します。
実際の山札、相手の非公開配置・配牌・捨て札は未知のままです。
乱数は局所的な random.Random を使い、ゲームの配牌乱数を消費しません。

相手の未知部分は簡単な配置方針で補完します。相手の過去の行動による推測や、
FL中の相手の最適配置・同時意思決定の完全なモデル化はしていません。
得点推定にはこの近似による偏りがあります。

## ナッシュ均衡について

今回のCPUは、ナッシュ均衡を求めたGTO戦略でも、厳密なISMCTS実装でもありません。
現在ターンの候補列挙と、ヒューリスティックを使ったモンテカルロ継続評価です。
局面の全網羅、均衡への収束、搾取されにくさ（exploitability）の上限は証明していません。

全てを調べる場合、山札だけでも52!通りあり、さらに配牌ごとの配置、捨て札、
非公開情報、FLの継続が加わります。現在の端末で3日計算すれば解けるという根拠はありません。

均衡を目指す次の研究段階では、以下を別途行う必要があります。

1. 対局の終了条件・長期のFL価値を定義し、情報集合を持つ2人零和ゲームとしてモデル化する。
2. スートの対称性などで状態を圧縮し、小さな部分ゲームでCFR/MCCFRの実装を検証する。
3. 自己対戦学習のチェックポイント・平均戦略を保存し、未使用の配牌で評価する。
4. 勝率だけでなく、最善応答による搾取可能性を測り、抽象化の誤差と均衡の誤差を区別する。

参考となる一次資料:

- [Cowling, Powley & Whitehouse (2012), Information Set Monte Carlo Tree Search](https://eprints.whiterose.ac.uk/id/eprint/75048/1/CowlingPowleyWhitehouse2012.pdf)
  は非公開情報下の探索と、単純な完全情報化による問題を扱っています。
- [Lanctot et al. (2009), Monte Carlo Sampling for Regret Minimization in Extensive Games](https://proceedings.neurips.cc/paper/2009/hash/00411460f7c92d2124a67ea0f4cb5f85-Abstract.html)
  はサンプリングによるCFRを扱います。今回の実装にMCCFR学習器は含まれていません。

## 検証の再現

以下は終盤の相手補完を追加する前の初版を、2026-10-17、Windows / Python 3.10 で測定した結果です。
最初の試行40ハンドとは別のシードで、Normal の製品設定（64サンプル上限・16候補・1.5秒上限）を100ハンド検証しています。

| 指標 | Normal | Easy（比較相手） |
|---|---:|---:|
| 勝率 | 64% | 35% |
| 引き分け | 1% | 1% |
| 平均得点差 | +3.37 | -3.37 |
| ファウル率 | 13% | 33% |
| FL進入率 | 8% | 6% |

ペア平均に基づく平均得点差の近似95%区間は +2.11〜+4.63点でした。
Normal の実測思考時間は平均0.353秒、最大1.016秒です（同一プロセス内の探索のみ）。
この差は簡単なルールCPUとの比較結果であり、熟練者に勝てることや均衡戦略を意味しません。
データは `cpu-benchmark-normal.json`、先行試行は `cpu-benchmark-pilot.json` を参照してください。

FL は14〜17枚を各4例、計16例の固定シードで別途確認しました。
すべて13枚の配置・残りの捨て札数が正しく、今回の16例ではファウル0件、
平均ロイヤリティ13.6875点、最大探索時間1.5秒でした。
小さなサンプルであり、全てのFL配牌でファウルを回避できるという保証ではありません。
生データは `cpu-benchmark-fantasy.json` にあります。

```powershell
.\.venv\Scripts\python -m unittest discover -v
.\.venv\Scripts\python -m tools.benchmark_cpu --pairs 50 --seed 20261018 --samples 64 --seconds 1.5 --output docs/cpu-benchmark-normal.json
.\.venv\Scripts\python -m tools.benchmark_fantasy
```

ベンチマークは同じ山札で探索CPUとEasyの座席を入れ替えるペア比較です。
通常ハンドを独立に評価し、FL進入は記録しますが次のFLハンドへは続けません。
平均得点差の95%区間はペア平均に基づく正規近似で、厳密な勝率保証ではありません。
時間制限がある測定は負荷やマシンで探索量が変わります。再現性を優先する際は
十分長い --seconds と固定 --samples / --seed を指定してください。

生の対局結果と実測時間は同じフォルダのJSONに記録します。
人間の熟練プレイヤー、外部の強いCPUとの評価は未実施です。

### 継続対戦の検証方法（2026-10-18追加）

`tools/benchmark_matches.py` は改良版 Normal と前回の Normal を比較します。
比較相手は `SearchConfig(opponent_aware_final=False)` とし、終盤以外の探索設定を一致させます。
同じ山札列で座席を入れ替え、通常ハンドから次回FLへ遷移させます。
通常側の全手番が終わってからFL側を配置し、両者FLの場合は相手の完成盤面を見せません。
FL継続時に元の枚数が維持されることも確認します。

試合は固定ハンド数で終了し、終了時の次回FL権には得点を加算しません。
FL進入が変われば配牌枚数も変わるため、同じ山札でも実際の配牌は途中から異なります。
信頼区間は個々のハンドを独立扱いせず、座席交換した試合ペア単位の平均から計算します。
時間制限のため実行負荷で探索量・結果が変わり得ます。

```powershell
.\.venv\Scripts\python -m tools.benchmark_matches --pairs 10 --hands 6 --seed 20261020
```

10組の座席交換、1試合6ハンド、合計120ハンドの結果は以下です。

| 指標 | 改良版 Normal | 前回の Normal |
|---|---:|---:|
| 平均得点差 / ハンド | +0.30 | -0.30 |
| ファウル率 | 21.7% | 24.2% |

平均得点差のペア単位の近似95%区間は −0.27〜+0.87点です。
ゼロを含むため、この小規模検証だけでは全体的な強さの向上を確認できません。
初版の対Easy測定とは相手・配牌・FL進行が異なるため、率を直接比較できません。
FLプレイヤーハンドは延べ18回、継続条件を満たしたのは4回でした。
両CPUを合わせた探索時間は平均0.706秒、最大1.516秒でした。
全120ハンドで配置の整合を確認し、FL継続時は元の枚数が維持されました。
生データは `cpu-benchmark-matches.json` に保存しています。

終盤の固定局面では、相手の完成盤面を同じモデルとして与えたとき、従来の自分の役だけの
採点では見落とした5点差を選択できる回帰テストを追加しています。これは局所的な判断の
改善を示すもので、未知の相手盤面の推定が常に正しいことを示すものではありません。
自動テスト29件が成功し、更新したWindows exeもリポジトリ外から起動して
実際の子プロセスによるCPU対戦1ハンドの得点精算まで確認しました。
