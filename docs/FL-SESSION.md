# FLが両者から消えるまで続くゲームの学習

## 確認したルールと学習単位

**どちらか一人でも次のファンタジーランド権を持つ限り、両者とも対局を続けます。**
FLを始めた側が抜けても、もう一方が新たにFLへ入れば続行です。
ハンド終了時に両者の次回FL権がなくなったところを、退出・精算できる境界とします。

学習の1エピソードは通常配牌から始まり、この境界までの全ハンドです。
報酬は各ハンドの実際の得点の合計で、割引・次回FLの固定ボーナスはありません。
そのため、通常ハンドのFL進入は、将来の実際のFL収益と相手の収益を通じて評価されます。
退出可能な境界からさらに任意に遊ぶ場合は、新しい学習エピソードとして扱います。

以下を実装しています。

- 通常側の全ストリートが終わってからFL側が配置する手番。
- 両者FLの場合、先に配置した側の非公開盤面を後の側に見せない処理。
- 現在の14/15/16/17枚を維持するFL継続。
- ハンド間の再シャッフルと、FL終了・再進入・相手へのFL交代。
- 自分の私的観測・行動、公表された途中盤面、各ハンドの結果の履歴保持。
  FL側も待機中に公開された通常側の配置順を記憶します。
- 両者の次回FL権がなくなるまで、終端報酬を取得できない状態モデル。

GUIでも、FL中または結果画面でどちらかに次回FL権がある間は、Escでメニューへ戻れません。
終了判定には古いFL状態ではなく、結果画面の**次回の権利**を使います。
OSの閉じる操作は利用できます。これは実験アプリの中断であり、学習上の退出・精算行動ではありません。
この更新に対局の自動保存・復帰は含まれません。

## 全配置モードと候補限定モード

FL全配置は、上段3枚・中段5枚・下段5枚・残り捨て札の組合せです。
行内の順番を区別せず、ファウルになる配置も合法な意思決定として含めます。

| 配牌 | 全配置数 |
|---|---:|
| 14枚 | 1,009,008 |
| 15枚 | 7,567,560 |
| 16枚 | 40,360,320 |
| 17枚 | 171,531,360 |

`--fantasy-candidates 0` が全配置モードです。全配置をリスト生成せず、番号から1手を復元できます。
ただし現行の表形式MCCFRは、各情報集合の全行動に後悔と平均戦略を保持します。
標準の `--max-actions 10000` ではFLに到達した時点で **ActionLimit** として停止します。
全配置を表現できることと、全配置を実用的な計算資源で学習できることは別です。
単に上限を1億以上に増やす運用は現実的ではありません。

`--fantasy-candidates 16` は別の、明示的な行動抽象化ゲームです。
公開観測と自分の手札から決まる固定乱数で256配置を候補化し、既存評価により16手を残します。
通常ターンは全合法手です。候補は同じ情報集合で常に同じ順序になります。
このモードの戦略が収束しても、元の全配置ゲームの均衡保証にはなりません。

## 計算上限で偽の精算をしない

ゲーム状態自体には「Nハンドで終了」というルールはありません。
学習器には計算資源を守る `--max-hands` / `--max-steps` / `--max-nodes` / `--max-actions` があります。
FLが残ったまま上限に達した場合、**その反復の更新と新規ノードを破棄し、乱数状態も戻して停止**します。
途中の累積点を終端価値として使わず、長いFLだけを飛ばして学習を続ける処理もしません。
上限を上げて再開すれば、止まった反復を同じ乱数系列からやり直します。
小さすぎるサンプリング到達確率も数値計算上の上限として停止します。

評価時も未終了の対局には得点を付けません。1件でも計算上限に達した場合は、
完了分だけで有利な平均を出すことを避け、全対局の平均点を未計算と表示します。

## 実行方法

リポジトリ直下から実行します。Python標準ライブラリで学習できます。

```powershell
# 通常配牌から始める。FLは16候補に制限した研究用ゲーム
python -m tools.train_mccfr --game session --fantasy-candidates 16 --iterations 1000 --checkpoint work/session.json --report work/session-results.json

# 同じモデルの続き。候補数と初期FL条件も一致させる
python -m tools.train_mccfr --game session --fantasy-candidates 16 --resume --iterations 1000 --checkpoint work/session.json --report work/session-resumed.json

# 14枚FL対17枚FLからの診断。通常開始モデルとは別のモデル
python -m tools.train_mccfr --game session --initial-tiers 14 17 --fantasy-candidates 16 --iterations 250 --checkpoint work/fl-diagnostic.json --report work/fl-diagnostic-results.json

# 全配置モードで計算上限の動作を確認（学習完了ではなくActionLimitで停止）
python -m tools.train_mccfr --game session --initial-tiers 14 17 --iterations 1 --checkpoint work/exact-guard.json --report work/exact-guard-results.json

# 未使用の山札列で、両者のFL権が消えるまで対Easy評価
python -m tools.evaluate_mccfr --game session --fantasy-candidates 16 --checkpoint work/session.json --pairs 20 --output work/session-evaluation.json
```

学習コマンドの既定ゲームは `session` に変更しました。旧モデルは `--game ofc` で利用できます。
`session` と旧通常1ハンドのチェックポイントは互換ではありません。
現時点のGUIの `--strategy` は旧 `ofc` モデル専用です。今回のsessionモデルは学習・評価用であり、
このMCCFRチェックポイントはGUIへはまだ接続していません。全ハンドの観測履歴を受け渡す実戦用アダプターが必要です。
別途、連続対局の実得点を教師値にした一般化価値モデルを [Hybrid CPU](HYBRID.md) に接続しています。
Hybridはここで保存したMCCFR戦略を読み込む方式ではありません。

通常開始の学習は20,017情報集合、FL開始の診断は1,030情報集合になりました。
全配置モードは14枚の1,009,008手が上限を超え、反復0・更新0で正しく停止しました。
これらは動作検証であり、均衡到達や十分な長期FL探索の証拠ではありません。

通常開始モデルの別シード40対局はすべて自然終了しました。平均得点は対Easyで−6.575点、
215判断中、学習済み情報集合への一致は0件でした。未学習局面は一様方策として評価しています。
**現時点では実戦的に強い学習済みCPUではありません。**
全47件の自動テスト、更新exeの子プロセスによる1ハンド対戦が成功しました。
1,500手の軌跡を再帰なしで処理できることと、処理方式変更前後の1,000反復の戦略・乱数状態の完全一致も確認しています。
生データは `mccfr-session-results.json`、`mccfr-session-fl-results.json`、
`mccfr-session-exact-guard.json`、`mccfr-session-evaluation.json` にあります。

## 終了性と均衡保証の区別

独立な一様シャッフルという実装上の仮定では、どちらもFL権を得られない配牌に正の確率があります。
具体的には、各プレイヤーに2〜Jのみ、各ランク2枚以下、同スートの5連続もないカード集合を配れば、
どの配置でも進入・継続条件を作れません。この構成をテストしています。
各FL枚数に対してそのような山札順を少なくとも1つ作れるため、保守的には1/52!をハンドごとの
終了確率の共通下限にできます。従って終了までのハンド数はほぼ確実に有限で、期待値も有限です。
この下限は極端に小さく、実用的な計算時間や誤差の保証には使えません。

ゲーム木の最大深さは固定されていません。有限ゲーム向けMCCFRの収束結果を、そのままこの実装の
全ゲーム保証として主張しません。元ゲームのexploitabilityは未計算です。
全ゲームの均衡を目指す次の課題は、巨大なFL行動空間のサンプリング学習、状態の対称性・抽象化、
継続局面の十分な再訪、近似最善応答と残存誤差の評価です。今回の更新は、その前提となる
**退出条件と連続ハンドの価値を正しくモデル化する段階**です。
