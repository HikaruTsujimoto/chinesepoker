# 候補間価値差を学習するAdaptive CPU

GUIの **CPU - Adaptive (test)** から利用する実験用CPUです。
モデルは `chinesepoker/ai/action_advantage.json` にあり、exeにも同梱します。
推論はPython標準ライブラリで動作し、NumPyは学習時だけ必要です。

## 前回の問題への対応

Hybridの線形モデルは候補の絞込みだけに使われていました。今回のAdaptiveでは、
候補ごとの学習値をロールアウト平均と混ぜて**最終着手を選択**します。
同じ候補集合でも学習結果が判断へ反映されることを回帰テストしています。
既知の修復不能な段の逆転を含む候補は、他の候補がある場合に除外します。

入力は183特徴です。従来の盤面特徴に、自分・相手の各段のランク別枚数、
既知の捨て札と未知カードのランク別枚数、各段のスートに対応した未知カード枚数、
相手のFL枚数、進行段階を加えています。スートの一括置換に対する対称性を保持します。
相手のFL枚数は公開情報としてGUIとシミュレータから渡し、非公開の手札は渡しません。
この特徴は完全な観測履歴や全スート・ランクの組合せを保存する表現ではありません。

小規模のtanhネットワークを使い、自分の配置と相手の盤面の相互作用を表現します。
最初の直接回帰モデルの検証結果が悪かったため、改訂版は旧ヒューリスティックを
学習データから尺度調整した事前評価とし、ネットワークがその修正量を学びます。
検証用の候補順位で学習途中の重みを選ぶため、この検証値は最終的な独立テストではありません。

## 教師データと自己対戦の更新

候補を旧評価の上位・現モデルの上位・ランダム探索から選び、同じ局面内の候補を
同じサンプル山札で比較します。選ばなかった候補に勝手な負のラベルは付けません。
候補間で共通の運による得点を取り除くため、予測と教師値を局面内で中心化した損失を使います。

通常手の後は、同一手番の配置が相手に見えない条件を維持して残りのハンドを進めます。
シミュレータに配牌予定が格納されていても、各CPUへはその時点のObservationしか渡しません。
未公開カードは既知のカードを除いた一様サンプルです。相手の過去行動から隠れた捨て札を
推定する完全な事後分布は実装していません。

1世代の学習後、固定したそのモデルを使って次世代の探索教師・自己対戦局面を作り直します。
局面収集には旧貪欲方策と現在の学習方策を混ぜ、10%の通常手探索も加えます。
これは近似的な方策改善です。NFSPの平均方策学習やDeep CFRの反実仮想後悔値学習そのものではありません。
教師の通常手継続方策は貪欲評価と現モデルの混合、実戦はさらにサンプル探索を使うため、
両方策は完全には同一ではありません。

## FLをまたぐ価値

現在のハンド得点に、次の両者のFL枚数に対応する継続価値を足します。
継続価値は0/14/15/16/17枚の組合せから、両者の次FL権がなくなるまで実際に対局して推定します。
異なる枚数の組合せは席を交換して計測し、同一方策の対称性から行列を反対称にします。
同じ枚数同士は期待得点差0ですが、個々の対局が0点という意味ではありません。
一度もFLを持たない(0,0)は境界時点で精算可能なので継続価値0です。

既存の固定FLボーナスを一度除いてから継続価値を足し、二重加算を避けます。
この値は固定した教師方策の推定であり、最適値ではありません。世代ごとに推定し直します。
教師のFL探索は計算時間を抑えるため1手0.04秒で、実戦のFL探索上限1.5秒とは異なります。
小標本の推定値にはばらつきがあり、枚数の大小と推定値が単調に並ぶ保証はありません。

資源上限でFLを打ち切った場合は例外で停止し、途中得点を終局報酬として保存しません。
ゲームの退出条件は変えません。FL配置そのものの最終選択は従来の多様化探索と固定継続ボーナスで、
今回の新しい行列は通常手の探索終端に接続しています。FLの配置方策への直接接続は今後の課題です。

## 今回の学習結果

初期の直接回帰モデルは、検証用の候補価値差が第1世代5.483（旧評価3.581）、
第2世代4.655（旧評価4.124）となり、旧評価を上回りませんでした。
その後、640学習局面・128検証局面、候補ごと8サンプル、各FL組合せ32往復対局で再学習しました。
検証値は新旧とも2.934723で、選ばれたのはニューラル補正0のモデルです。
旧評価の尺度係数は0.06278982です。ネットワークを用意・学習できたことと、
そのネットワークで強くなったことは区別する必要があります。

したがって今回の配布モデルの変更は、尺度調整した旧評価を探索結果と混ぜることと、
推定したFL継続価値の使用が中心です。非線形補正の効果は確認できていません。
`action-training.json` と `action-refinement-training.json` に失敗した初期学習も含めて記録しています。
初期学習は残差方式への変更前に実行したため、以下の現行コマンドで初期の数値を再現するものではありません。

## 実行コマンド

Pythonの学習環境に `pip install -r requirements/training.txt` でNumPyを追加します。
今回の学習は同梱のPython環境とNumPy 2.3.5で実行しました。ゲームのPython 3.10環境とは分離できます。

```powershell
python -m tools.train_action_model --generations 2 --groups 160 --validation 40 --samples 4 --fl-pairs 8
Copy-Item chinesepoker/ai/action_advantage.json training-data/bootstrap-final.json
python -m tools.train_action_model --initial-model training-data/bootstrap-final.json --seed 60000000 --generations 1 --groups 640 --validation 128 --samples 8 --fl-pairs 32 --report docs/action-refinement-training.json
python -m tools.evaluate_hybrid --variants action --pairs 32 --seed 80000000 --output docs/action-evaluation.json
python -m tools.evaluate_hybrid --variants adaptive --pairs 16 --seed 81000000 --output docs/adaptive-evaluation.json
python -m chinesepoker --cpu-smoke-test --cpu-level adaptive
```

`bootstrap-final.json`は前の学習で得たモデルのコピーです。
現在の学習器は世代ごとのモデルと教師データを `training-data/` に保存します。
`--initial-model` は保存モデルから次の方策改善を始める指定です。
処理途中の乱数・最適化状態まで完全復元する再開ではありません。
モデルと最終評価のseed範囲を分離し、学習時の時間制限による完全再現性の限界も記録します。

## 均衡学習の検証を分離する

実戦CPUとは別に `tools/deep_cfr_kuhn.py` を追加しました。
[Deep CFR (Brown et al., 2019)](https://proceedings.mlr.press/v97/brown19b.html)の
外部サンプリング、反復番号で重み付けしたreservoir、毎更新時に再初期化する後悔値ネットワーク、
別の平均方策ネットワークを、小さなKuhn Pokerで検証します。
完全に同じ情報集合のサンプルを平均化して回帰していますが、これはサンプルごとの二乗誤差と
勾配が同じになる集約であり、異なる情報集合を混ぜる抽象化ではありません。

```powershell
python -m tools.deep_cfr_kuhn --iterations 200 --traversals 100
```

今回のseed 7、200反復の平均方策は、厳密な最善応答評価でexploitability **0.011733**、
プレイヤー0の価値 **-0.055686** でした。結果と平均方策ネットワークは `deep-cfr-kuhn.json` に保存します。
この実装の状態エンコーダはKuhnの12情報集合専用です。OFCの学習器として動くとは主張しません。
OFCへの拡張にはFLの行動サンプリング・情報履歴・継続価値近似の誤差検証が残っています。

自己対戦更新の比較対象として [NFSP](https://arxiv.org/abs/1603.01121)、
複数局をまたぐ報酬設計の参考として [Suphx](https://arxiv.org/abs/2003.13590) を参照しています。
現状のAdaptiveがこれらの方式を完全に実装した、またはナッシュ均衡に達した、とは扱いません。

## 独立した対戦評価（2026-10-18）

学習とは異なる配牌seedを使い、Normalと同じ1手1.5秒上限・64サンプル・候補16で比較しました。
開始時は両者通常、両者とも次FL権を失った時点を1対局の終わりとし、席を交換した2対局を1組とします。
全対局が精算まで完了し、途中打切りは0件でした。

| 変更範囲 | 対局数 / ハンド数 | 平均得点差 / 対局 | 組単位の近似95%信頼区間 | 新 / 旧ファウル数 |
|---|---:|---:|---:|---:|
| 通常手の変更のみ（action） | 64 / 82 | +0.344 | −1.841〜+2.529 | 12 / 13 |
| FL探索を含むAdaptive全体 | 32 / 43 | +4.500 | −1.230〜+10.230 | 6 / 7 |

どちらも区間が0を含み、旧Normalに対する優位性は確認できません。
2つの比較は配牌seedが異なるため、平均値の差をそのままFL探索の効果と解釈できません。
実測の平均思考時間はactionで新0.509秒/旧0.389秒、Adaptive全体で新0.488秒/旧0.386秒でした。
時間上限による探索なので、同一seedでも実行環境によって結果が変わります。
個別対局と配布モデルのSHA-256は `action-evaluation.json`、`adaptive-evaluation.json` に保存しています。

同じ通常局面100件・同じ64サンプルを完了させる比較では、旧Normalから着手が変わったのは8件でした。
最初の5枚の配置では20件中5件、残りの各ストリートでは1/20、1/20、1/20、0/20件です。
ニューラル補正を0にした場合との差は0件で、今回の配布重みが補正0であることと整合しています。
この着手差は強さの証明ではありません。詳細は `action-diagnostics.json` に記録しています。

Windows exeを作成し、同梱画像・同梱モデル・別プロセスCPUを使う1ハンドのスモークテストが終了コード0で完了しました。
テストは合計69件を検証済みです（ゲーム環境で62件、NumPyを必要とする7件は学習環境で実行）。

## 次の学習で優先すること

今回の結果だけで、ネットワークの規模や学習時間を増やせば改善するとは判断できません。
まず固定した局面で教師サンプル数を増やし、候補順位の安定性を測る必要があります。
次に、教師の継続方策を実戦の探索方策へ近づけ、FL継続価値も同じ探索予算で推定します。
その後に、候補ランキングの独立テストで旧評価を上回ったモデルだけを対戦評価へ進めます。
特徴表現・相手方策の履歴集合・全ゲームのDeep CFRへの拡張は、この検証を分けて進める対象です。
