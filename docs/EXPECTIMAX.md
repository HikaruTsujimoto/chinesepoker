# 配牌ごとの最善配置を読む期待値探索

GUIで **Play vs CPU** を選択します。既定の探索予算は1手10秒です。画面には思考中の状態だけを表示し、経過秒数は表示しません。
以前のCPUは無効化し、復元用のコードと資料を保管しています。カード画像とFL継続価値モデルはexeに同梱します。

## 何を最適化するか

現在の合法な配置・捨て札ごとに、次の配牌を平均し、その配牌を見てから選べる最善配置を求めます。
基本式は `V(盤面, 未知カード) = 平均_配牌 [ 最大_配置 V(次盤面, 残り未知カード) ]` です。
配牌の3枚は、捨てる1枚も含めて残りカードから除きます。
将来の配牌ごとに過去の配置を選び直す「未来を知った最適化」はしません。

通常手が完成したときの目的関数は、相手とのハンド実得点と、次の両者のFL枚数に対応する継続価値の和です。
自分の役のロイヤリティだけでなく、段の勝敗、全段勝利ボーナス、ファウルを評価します。
継続価値は前回保存した固定方策での推定行列を使用し、今回再学習はしていません。
両者とも次FL権を持たない場合は継続価値0で、ゲームの精算条件は変わりません。

今回の拡張では候補数を12から24、外側の配牌サンプル上限を64から128、探索予算を5秒から10秒に変更しました。以下の過去の対戦成績は拡張前の設定の結果であり、新設定の強さはまだ比較評価していません。

## 実戦での探索範囲

| 現在の配置済み枚数 | 現在の候補 | 続きの探索 |
|---|---|---|
| 0 / 5 | 旧評価上位24候補 | 次の配牌を最大128サンプルで比較し、次の配置は全列挙。その先は貪欲配置の2ロールアウトで近似 |
| 7 | 旧評価上位24候補 | 残り2回の配牌・配置まで読む。内側の配牌は原則2サンプルで期待値近似 |
| 9 | 全候補 | 最後の3枚の全組合せをランダム順に列挙し、各配牌の最終配置を全列挙。時間切れ時は完了分の平均 |
| 11 | 全候補 | 完成盤面の目的関数を比較 |
| FL | 既存の多様化探索 | 時間制限付き配置探索。FL配置そのものの新しい厳密最適化は未実装 |

現在の全候補を同じ配牌サンプルで評価し終えたバッチだけを採用します。
時間切れで途中になったバッチは捨てます。1バッチも完了しなければ合法な旧評価の候補を返し、
診断メッセージに `heuristic fallback` と記録します。
計算した値を同一探索内でキャッシュしますが、期限超過による未完了の値は保存しません。

## 相手と未知カードの近似

未来の自分の配牌を観測する節点でも、相手の未公開手札や将来の実際の山札は渡しません。
自分が既に見た手札・捨て札・公開盤面を除き、残りを一様にサンプリングします。
完成盤面の価値を比較する際は、残りカードから作った4つの相手完成盤面の平均を使用します。
候補間で同じ相手サンプルを共有し、単一の隠れた相手盤面を知って着手する扱いにはしません。
相手がFLなら公開されたFL枚数で既存のFL探索を使います。

相手の将来の公開配置を途中で観測して対応する分岐は実装していません。
相手の公開盤面を現在の状態で固定し、通常相手の継続配置は既存の貪欲方策で近似します。
相手の過去行動から隠れた捨て札を推定する完全な事後分布でもありません。
FL相手の配置モデルも、こちらの仮想的な完成盤面を見て配置を変える応答モデルではありません。
そのため、未知カードの厳密な分布や全ゲームの最適方策を解いたとは主張できません。
最大値を取る探索には、少数サンプルの誤差を過大評価する偏りも残ります。

## 厳密計算と検証

`chinesepoker.ai.expectimax.exact_value` は、指定した有限の残り山札・終端目的関数について、
全配牌と全配置を再帰的に列挙する検証用APIです。初手5枚を置いた後の通常局面に対応します。
相手の戦略まで最適化するAPIではありません。
状態数上限を超えると例外になり、近似値を厳密値として返しません。
実戦のメソッド表示も、終盤の必要な全配牌・全候補を完了し相手盤面が既知の場合だけ
`exact own-hand objective` とします。この表示でもFL継続価値自体は推定値です。

残り山札7枚・未来2配牌・相手完成盤面固定の12局面では、厳密最適化が貪欲継続方策より
平均 **3.474368点** 高い目的関数値でした。全12局面で貪欲方策以上でした。
これは縮小問題の検証であり、通常の52枚デッキでの対戦成績とは区別します。
各局面と結果は `expectimax-endgame.json` に保存しています。

追加テストでは、2回の配牌を含む手計算相当の全列挙との一致、未来を知る不正な計算との値の差、
捨て札の除外、状態数制限、相手既知の最終手、期限0での合法手、未知カードの情報境界を確認します。
全77テストを検証済みです（ゲーム環境70件、NumPy学習環境7件）。

```powershell
python -m unittest discover -v
python -m tools.evaluate_expectimax_endgame
python -m tools.evaluate_hybrid --variants expectimax --pairs 8 --seconds 5 --seed 90000000 --output docs/expectimax-evaluation.json
python -m chinesepoker --cpu-smoke-test --cpu-level expectimax
```

実戦評価は両者の思考上限を5秒に揃え、旧Normalのサンプル数64・候補16と比較します。
これは既定の1.5秒Normalや256サンプルのHardとの比較ではありません。
FL配置も含めたCPU全体の比較なので、通常手の期待値探索だけの効果を分離した評価でもありません。
少数対局から優位性を断定せず、席を入れ替えた組単位の信頼区間を併記します。

## 実戦評価結果（2026-10-19、拡張前の設定）

8組16対局・計25ハンドで平均 **+10.3125点/対局**、組単位の近似95%信頼区間は
**−2.7006〜+23.3256点**でした。小標本で区間が0を含むため、旧CPUへの優位性は未確定です。
全対局が両者の次FL権がなくなるまで完了し、途中打切りは0件でした。
ファウルは新旧とも2/25ハンド、FLプレイヤーハンドは合計10回でした。

上限は双方5秒ですが、旧CPUは64サンプルで探索を終了するため、実測平均は
Expectimax **4.0758秒**、旧CPU **0.4327秒**でした。同じ実計算量での比較ではなく、
得点差を探索方式だけの改善量とは解釈できません。
Expectimaxの93着手のうち通常手85回・FL8回で、通常手の `heuristic fallback` は0回でした。
相手の未知カードがあるため、実戦で厳密値と判定した着手は0回です。
各対局、着手の探索方法、思考時間、継続価値モデルのSHA-256は `expectimax-evaluation.json` に保存しました。

Windows exeをビルドし、同梱画像・モデル・別プロセスCPUによる1ハンドのスモークテストは終了コード0で完了しました。
